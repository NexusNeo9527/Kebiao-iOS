## 问题明细

### A01 · P1 · 停课周仍会收到通知

位置：`Kebiao/ReminderScheduler.swift:37–51`。

每门课按星期创建 `repeats: true` 的通知，未检查 `startWeek`、`endWeek` 或 `activeWeeks`。例如仅第 2–9 周上课，或只在双周上课，通知仍每周重复。修复应按实际有效课程日期安排通知，并处理系统待处理通知数量上限和后续补排策略。

### A02 · P1 · 合并导入覆盖不同周次的课程

位置：`Kebiao/TimetableStore.swift:72–78,101–115`。

去重签名只有名称、教师、地点、开始节次和星期，没有周次、连续节数或自定义开始时间。同一课程、教师、教室、周一第 1 节，分别在第 1–8 周和第 9–16 周上课，合并导入后后者覆盖前者，前半学期课程消失。需要区分课程安排身份与课程名称身份。

### A03 · P1 · 普通导入会错误识别周次

位置：`Kebiao/ScheduleImportService.swift:728,852–859`，文字 PDF 回退还使用 `:489`。

`weekRange` 只取一个连续范围或前两个数字。`1-16周(单)` 会变成每周；`2-9周,14-16周` 会只保留第一个范围。更严重的是没有周次字段时，`周一第3-4节` 中的数字 3 和 4 被当成第 3–4 周，导致其他周隐藏该课程。网格 PDF OCR 的 `pdfWeekNumbers` 有精确集合实现，但通用导入没有使用它。

### A04 · P1 · 学期周使用固定日期，跨年会重置错误

位置：`Kebiao/ScheduleEngine.swift:41–50`。

周次固定从每年 9 月 1 日或 2 月 15 日所在周计算，不能配置学校实际开学日期。2027 年 1 月的日期被归入尚未开始的 2027 年春季学期，并因 `max(1, ...)` 显示第 1 周，无法延续 2026 年秋季学期。所有按周过滤的课表、日程、小组件和实时活动都会受影响。

### A05 · P1 · ICS 导入改变原日历安排

位置：`Kebiao/ScheduleImportService.swift:670–710,924–947`。

只提取开始时间和 `BYDAY`，不保留 `COUNT`、`UNTIL`、`INTERVAL`、`EXDATE` 或单次事件的实际日期。仅一次的事件或限定两次的课程也被转换成默认第 1–20 周的每周课程。`TZID` 参数也没有传给日期解析器：带 `TZID=America/New_York` 的本地时间按设备当前时区解释。无法支持的规则应明确告知用户，避免静默产生额外课程。

### A06 · P1 · 部分教务页面读取失败

位置：`Kebiao/SchoolPortalLoginView.swift:87–101`，`Kebiao/ScheduleImportService.swift:48–53,418–434`。

网页脚本拼接所有表格，解析器却只使用第一行作为唯一表头。实际脚本执行结果：当导航表格在课程表格之前时，首行为 `导航\t链接`，课程名称、星期等列无法映射。脚本也只读取顶层 document；iframe 内课表没有被遍历，父页面无文字时实际输出为空。应识别各表格的课程表头，并为 iframe 情况提供可用的读取或替代导入路径。

### A07 · P1 · 关闭提醒的课程阻塞后续灵动岛

位置：`Kebiao/LiveActivityCoordinator.swift:5–12`。

先从所有课程选择最近课程，再检查它是否启用提醒。若 08:00 的课程关闭提醒、09:00 的课程开启提醒，选中前者后会 `endAll()` 并退出，后者无法被选中或预排。需要先过滤可提醒课程，再寻找发生时间。

### A08 · P2 · 编辑课程后灵动岛继续显示旧资料

位置：`Kebiao/LiveActivityCoordinator.swift:31–35,91–95`，`Kebiao/ClassActivityAttributes.swift:9–17`。

现有活动只比较课程 ID 和开始日期，命中后立即退出。课程名、教室、教师、结束时间等放在 attributes 中；只修改这些字段不会更新或重建活动。修改连续节数时还会保留旧结束时间。

### A09 · P2 · 日程的“下一节课”和已完成状态不可靠

位置：`Kebiao/TimetableStore.swift:33–35`，`Kebiao/DayScheduleView.swift:14–19,28`。

日程沿用按开始节次排序，未按实际自定义开始时间排序。例如第 1 节自定义为 18:00，第 3 节自定义为 09:00，早上优先显示的“下一节课”仍可能是 18:00。已完成判断依赖 `.now`，但该页面没有周期性更新或时间边界刷新机制，持续停留页面时不保证课程结束后及时进入“已完成”。

### A10 · P2 · JSON 导入与本机 Course 数据格式不一致

位置：`Kebiao/ScheduleImportService.swift:641–665,714–745`，`Kebiao/Models.swift:4,38–54`。

JSON 全部转成通用字符串字典，没有按原生 Course 的 Codable 格式解码。`startTimeMinutes`、`startWeek`、`endWeek`、`activeWeeks`、`colorValue` 和 `reminderMinutesBefore` 未映射；原生星期 raw value 2 表示周一，通用 JSON 的 2 却表示周二，原生周日 8 无法识别。当前并无导出按钮，因此这主要影响导入已有本机格式数据及结构化文件的兼容性，应明确支持格式或增加原生格式检测。

### A11 · P2 · 无“节”字的节次范围被截断

位置：`Kebiao/ScheduleImportService.swift:723–725,861–866`。

`sectionRange` 要求末尾有“节”。显式节次列为 `5-7`、没有连续节数字段时，会取开始节 5 并使用默认 2 节，而正确应是 3 节；`7-7` 同样会默认成 2 节。显式节次字段应支持无单位范围，同时避免把周数或时间误识别为节次。

### A12 · P2 · 深色模式下固定白色卡片与自适应文字冲突

位置：`Kebiao/KebiaoTheme.swift:4–5`，`Kebiao/CoursesView.swift:72,89`，`Kebiao/DayScheduleView.swift:159–177`。

背景和卡片固定为浅色或白色，文字多用随系统变化的 `.primary`、`.secondary`，没有统一限制浅色模式。深色模式下 `.primary` 文字会变浅，在白色卡片上对比度不足。需要统一支持深色主题或明确采用浅色外观；具体屏幕效果尚未渲染验收。
